## What's confirmed from other docs

- Supabase is the primary datastore for users, fixtures, predictions, results, leaderboard, and
  official group standings — see [Architecture](/architecture) for the canonical schema of each
  table.
- Firestore remains a legacy backup/fallback data source; removing the remaining Firestore
  read/write calls from `app.js` and the worker is an open item on the [Fix Plan](/plan).
- The Apps Script backend tries Firebase first, falls back to Supabase, and includes a one-shot
  Firestore-to-Supabase migration path.
- Supabase RLS policies were part of prior hardening work — see the [Changelog](/changelog) for
  related entries, and confirm current policy state before relying on this page.
