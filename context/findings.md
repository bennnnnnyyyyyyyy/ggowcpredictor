# Findings

## Bracket UX
- The current bracket plan already assumes a fixed knockout tree driven by `group_standings` and prior results.
- The user wants the bracket to behave more like the prediction cards: clearer metadata, larger cards, and lower vertical spacing.
- The user does not want the bracket to feel overly zoomed out.

## Autofill behavior
- Autofill should happen when knockout participants are confirmed after the group stage ends.
- The plan should treat group qualification as a data transition, not a manual UI step.
- The bracket should still display unresolved slots as `TBD` until the source data is actually confirmed.
